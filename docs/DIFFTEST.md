# Differential testing: how the C code is checked

We have no copy of Visco's exact compiler, so the C in `src/game/` isn't checked
by rebuilding the ROM. Instead, every function is **run side by side with the
original**:

1. The original MIPS code runs in the [Unicorn](https://www.unicorn-engine.org/)
   emulator, loaded from your `baserom.z64` at its real addresses.
2. The C version is compiled **for MIPS** with clang (`tools/difftest/mipsbuild.py`)
   and loaded at `0x80700000` in the same emulator, so it uses the same 32-bit
   big-endian memory layout and the same game globals.
3. Both get identical inputs: random numbers, random buffers, or real game data
   such as every sprite asset in the ROM. Then every return value and every byte of
   memory they touch is compared.

Pure maths functions are also compiled natively and compared bit for bit
(`autotest.py`).

| Test | What it checks |
|---|---|
| `autotest.py` | vd_math.c: 25 geometry functions, bit-exact floats, 300 random inputs each |
| `test_funcs.py` | matrix.c (including aliased in/out pointers) and sprite placement |
| `test_heap.py` | heap.c: 150 random alloc/free sequences; return values and the whole heap |
| `test_siff_writer.py` | Siff chunk writer, 300 random sessions |
| `test_sprite.py` | Sprite_Parse and friends on **all 472 sprites**, plus Asset_LoadLzss on all 472 compressed assets; whole 2 MB heap compared |
| `test_screen_sprite.py` | screen sprites: load + 300 random redraws at both screen widths |
| `test_photoview.py` | photo scrolling, mosaic effect, rectangle copy |
| `test_funcs.py libm` | libm.c: 28 maths functions incl. 3x3/4x4 inverse (affine and general) |
| `test_strutil.py` | keyword matchers, CRC16, `sprintf` (random formats, flags, widths), hex dumps |
| `test_geom.py` | geom.c: hit tests on realistic triangles/meshes, triangulation, radix sorts |
| `test_rotate.py` | rotate.c: 27 matrix builders, incl. singular and aliased cases |
| `test_collide.py` | collide.c: mesh batching on 400 random meshes, pools, RNG, splines |
| `test_scene.py` | scene.c: node pool, random trees, display lists, camera, lights |
| `test_object.py` | object.c: all 70 object functions, whole BSS + 2 MB heap compared, real ROM sprites |
| `test_text.py` | text.c: random strings/colours/screen widths with the real ROM font |

| `test_system.py` · `test_audio.py` · `test_gfx.py` | system/boot, audio, graphics/input/coins; libultra calls stubbed and call logs compared |
| `test_mainloop.py` · `test_jpeg64.py` | main loop (scripted overlay results); photo decoder/encoder on **synthetic data only** |
| `test_ovl0.py` · `test_ovl1.py` · `test_ovl3.py` | test mode, attract/title, girl select: whole screens run frame by frame |
| `test_ovl2_a.py` … `test_ovl2_d.py` | the game overlay: full rounds, bosses, items, bonus stage, frame by frame |

The whole suite (`run_all.py`) takes about 70 minutes on a 2-core machine; each test
accepts function names (and most a `TRIALS=` setting) for quick runs.

Known difference, on purpose: `Mesh_InterpolateAt` (0x80002558) in the original reads
three x coordinates from the stack before writing them (leftover values). The C uses the
real values, which is what was clearly intended; the test primes the original's stack so
both agree. Notes from each area (struct layouts, quirks kept) are in `docs/notes/`.

A handful of other places in the original read memory that was never written (leftover
stack or register values) on rare paths; the C uses 0 there and the tests set the
original's leftovers to 0 too. Each is listed in the notes: `Title_Main` (service switch
on the first frame), `Game_Main` early aborts, `Player_CloseArea`, `Bonus_Task` result
word, the snake beam target, and `Test_Run` with an invalid mode. None of these change
normal play.

ROM data reads (`Rom_Read`) are served straight from the ROM by a Python stub.

## Running it (optional, for developers)

On Linux, everything is available as packages. On a Mac:
```
brew install llvm
```
```
pip install unicorn
```
Then, from the project folder (with `baserom.z64` and `gmake setup` done):
```
python3 tools/difftest/run_all.py
```
`mipsbuild.py` expects `clang` (with the MIPS target) and `mips-linux-gnu-` binutils;
change `BIN` at the top of that file to `mips64-elf-` for Homebrew's binutils.

## Writing a new function

1. Draft: `src/draft/*.c` (generated by m2c) has a first version of every function.
2. Write the clean version in `src/game/`, with a `/* @ 0x8000xxxx */` comment
   right before it, naming the original address.
3. Keep floating-point expressions in **exactly** the same order as the original;
   results change otherwise.
4. Add it to a test (or `test_funcs.py`'s table) and run it. A real bug shows up
   straight away as a byte difference.
5. Run `python3 tools/progress.py`, and add the name to `symbol_addrs.txt`.
